semantic\_statistic.py
======================

.. currentmodule:: semantic_statistic

.. autofunction:: main

.. rubric:: Overview

``semantic_statistic.py`` aggregates **semantic feature statistics** per Apollo module for a given
version (``6/7/8/9``). It reads per-bitcode JSON analysis results (currently generated by Saber),
clusters them by module using the bitcode-to-source mapping table, and sums selected field groups.

The script provides an interactive list of semantic field groups (for example ``abs_scale``,
``pt_complex``, ``call_graph``, ``mem_access``), and exports aggregated values as a module-indexed CSV.

.. rubric:: Output

The script writes a CSV file to:

- ``PROJECT_ROOT/results/semantic_statistic_{FIELD}_v{VERSION}.csv``

Where ``{FIELD}`` is the selected field group name. The CSV is indexed by ``module``, and columns
are derived from the leaf keys of the selected field paths.

.. rubric:: Usage

.. warning::

   You should have run ``extract.py``, ``name_mapping.py``, and ``saber_analyze.py`` once before
   running this script for the given ``{VERSION}``.

- Non-interactive version argument (field selection is still interactive), e.g. :

.. code-block:: bash

   python semantic_statistic.py 9

- Fully interactive (you will be prompted for ``6/7/8/9`` and then field index):

.. code-block:: bash

   python semantic_statistic.py

.. rubric:: Arguments

- ``version``: Apollo version number. Supported values are ``6``, ``7``, ``8``, and ``9``.

.. rubric:: Interactive field selection

After version validation, the script prints all available field groups and asks for an index:

- enter an integer in range ``1..N`` to select one field group

.. list-table::
   :header-rows: 1
   :widths: 12 28 60

   * - Index
     - Field name
     - Description
   * - 1
     - ``abs_scale``
     - Overall abstract scale metrics (objects, pointers, SVF statements).
   * - 2
     - ``pt_complex``
     - Pointer-analysis complexity indicators (addresses, GEPs, load/store/copy stats).
   * - 3
     - ``obj_ingredient``
     - Composition of object kinds (heap, stack, global, function objects).
   * - 4
     - ``call_graph``
     - PTA call-graph size and structure metrics (nodes, edges, cycles).
   * - 5
     - ``svf_statistic``
     - Core SVFG graph statistics (total nodes/edges, direct/indirect edges).
   * - 6
     - ``formal_dep``
     - Formal-side dependency counts in SVFG (in/out/param/ret).
   * - 7
     - ``actual_dep``
     - Actual-side dependency counts in SVFG (in/out/param/ret).
   * - 8
     - ``mem_access``
     - Memory SSA access metrics (regions, :math:`\phi`, :math:`\mu`, :math:`\chi` nodes).
   * - 9
     - ``inter_mem``
     - Interprocedural memory-flow indicators (entry :math:`\chi`, return :math:`\mu`).
   * - 10
     - ``pointer_mem``
     - Pointer-related memory indicators (null pointers, indirect calls, cycle nodes).

.. rubric:: Troubleshooting

- If you see "Invalid version number", make sure the input is one of ``6/7/8/9``.

- If it reports mapping file missing, run :doc:`name_mapping.py <name_mapping>` first to generate
  ``results/bc_mapping_v{VERSION}.json``.

- If it reports result JSON directory/file missing, run :doc:`saber_analyze.py <saber_analyze>` first to generate
  ``results/saber_json_v{VERSION}/``.

- If the analysis container cannot run while producing prerequisite results, see
  :doc:`RESOURCES/Analysis Toolkits </resource/analysis/docker>`.
